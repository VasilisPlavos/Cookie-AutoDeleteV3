# Clear 3 High-Severity Vulnerabilities Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clear all 3 high-severity `npm audit` advisories (`serialize-javascript` ×2, `braces` ×1) by adding npm `overrides`, with no parent upgrades and no node-floor change.

**Architecture:** Add an `overrides` block to `package.json` pinning `serialize-javascript@^7.0.5` and `braces@^3.0.3`. These force the two vulnerable transitive copies (cwp@10's bundled serialize-javascript@6.0.2, and jest@26/sane's braces@2.3.2) to patched releases without touching any direct dependency. Correctness is proven by running `npm audit`, the test suite, and the webpack build.

**Tech Stack:** npm `overrides` (npm 8.3+; project has npm 11.8), jest 26, webpack 5, copy-webpack-plugin 10.

**Reference spec:** `docs/superpowers/specs/2026-06-12-clear-high-severity-vulns-design.md`

### Task 1: Add npm overrides and regenerate lockfile

**Files:**
- Modify: `package.json` (add top-level `overrides` block after `devDependencies`, before `scripts`)
- Modify: `package-lock.json` (regenerated by `npm install`)

- [ ] **Step 1: Capture the baseline audit (verify it fails)**

Run:
```
npm audit
```
Expected: report ends with a line containing `3 high` (e.g. `26 vulnerabilities (3 low, 20 moderate, 3 high)`). This is the failing baseline we will drive to zero highs.

- [ ] **Step 2: Add the `overrides` block to package.json**

In `package.json`, insert a new top-level `"overrides"` key immediately after the closing brace of `"devDependencies"` and before `"scripts"`. The exact text to add (note the trailing comma after the closing brace so the following `"scripts"` key stays valid JSON):

```json
  "overrides": {
    "serialize-javascript": "^7.0.5",
    "braces": "^3.0.3"
  },
```

After the edit, the relevant region of `package.json` reads:
```json
    "webpack-cli": "^4.10.0"
  },
  "overrides": {
    "serialize-javascript": "^7.0.5",
    "braces": "^3.0.3"
  },
  "scripts": {
```

- [ ] **Step 3: Regenerate the lockfile**

Run:
```
npm install
```
Expected: completes without errors; `package-lock.json` is updated. If npm prints `npm warn ... overridden` lines for serialize-javascript / braces, that is expected and fine.

- [ ] **Step 4: Verify the overrides resolved as intended**

Run:
```
npm ls serialize-javascript braces
```
Expected: every `serialize-javascript` entry shows `7.0.5` (no `6.0.2`), and every `braces` entry shows `3.0.3` (no `2.3.2`). If any `2.3.2` or `6.0.2` remains, the override key name or range is wrong — fix and re-run `npm install`.

- [ ] **Step 5: Commit**

```
git add package.json package-lock.json
git commit -m "fix(deps): override serialize-javascript and braces to patched versions"
```

This task adds no code — it is the acceptance gate from the spec. Do not mark the work done until all four gates pass.

- [ ] **Step 1: Audit — zero high severity**

```
Expected: the summary line no longer contains `high` (e.g. `23 vulnerabilities (3 low, 20 moderate)`). Moderate and low advisories remaining is acceptable and out of scope. If any `high` remains, re-check `npm ls serialize-javascript braces` from Task 1, Step 4.

- [ ] **Step 2: Run the test suite**

Run:
```

```
Expected: jest runs to completion with all suites passing (same pass/fail status as before the change). The braces override touches only jest's watch-mode `sane` path, which `jest --coverage` does not exercise — so a green suite confirms no regression.

- [ ] **Step 3: Run the webpack build**

```

```
Expected: webpack completes with no errors. copy-webpack-plugin (now serializing via serialize-javascript@7.0.5) emits the global files; confirm `extension/global_files/` contains `bootstrap.min.css`, `bootstrap.bundle.min.js`, and `jquery.slim.min.js`.

- [ ] **Step 4: Final sanity commit (only if Task 1's build/test surfaced any needed tweak)**

If Steps 1–3 all passed with no further changes, there is nothing to commit here — the fix from Task 1 stands. If a tweak was required (e.g. an override range adjustment), commit it:
```
